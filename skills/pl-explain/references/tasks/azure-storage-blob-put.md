# azure-storage-blob-put

> Reference token: DF-TASK-AZURE-STORAGE-BLOB-PUT-01

Status: GA | Category: storage | Documentation: https://learn.product-live.com/data-factory/references/tasks/azure-storage-blob-put/

## Purpose

Upload a list of files, each given by URL, as block blobs into a Microsoft Azure Storage container, with optional metadata per blob. The list is an XML request file.

## When to use

- Push generated files or images to Azure (product images exported from the platform, PDFs generated by a job).
- Mirror the output of an export into a customer's storage account.

## When not to use

- More than 1000 files, a file above 2 GB or more than 20 GB in total: the limits are not checked up-front and the upload stops part-way.
- Uploading to an FTP or SFTP server: use `protocol-ftp-post`.

## Inputs

| Name | Type | Required | Default | Allowed values | Meaning |
| --- | --- | --- | --- | --- | --- |
| authenticationMode | ENUM | yes | - | CONNECTION_STRING, SHARED_KEY, SAS_TOKEN | Authentication mode. |
| connectionString | STRING | when authenticationMode = CONNECTION_STRING | - | - | The Azure Storage connection string. |
| sharedKey | STRING | when authenticationMode = SHARED_KEY | - | - | The shared key. |
| sasToken | STRING | when authenticationMode = SAS_TOKEN | - | - | The SAS token. |
| account | STRING | when authenticationMode = SHARED_KEY or SAS_TOKEN | - | - | The storage account name. |
| container | STRING | yes | - | - | The target container. |
| request | FILE | yes | - | - | XML file listing the blobs to upload (structure below); typically the output of an earlier task, for example `${build_request.output.result}`. |
| skipReportGeneration | BOOLEAN | no | false | true, false | When `true`, no report is generated and `report` is absent from the outputs. |
| logLevel | ENUM | no | info | error, warning, info, debug | Log level recorded in the report. |

`request` structure (verbatim from the documentation):

```xml
<Azure-Storage-Blob-Put>
    <File>
        <Url>https://myaccount.blob.core.windows.net/images/product-image-1.jpg</Url>
        <Name>img/products-1.jpg</Name>
        <Metadata>
            <ean>1234567890123</ean>
            <hash>8cca35ef9731da58ba0826e01e2c9047e41ba3e8692282de7999bf601d7adc88</hash>
        </Metadata>
    </File>
</Azure-Storage-Blob-Put>
```

| XPath | Meaning | Occurs |
| --- | --- | --- |
| `/Azure-Storage-Blob-Put` | root | 1 |
| `./File` | one element per file to upload | 0 or more |
| `File/Url` | complete URL of the source file | 1 |
| `File/Name` | blob name; must not start with `/`; its extension determines the blob content type, and a file whose extension cannot be resolved is skipped | 1 |
| `File/Metadata` | key/value pairs (element name = key), sent as-is; names must follow the Azure rules (letters, digits, underscores; no space, no hyphen, not starting with a digit) or Azure rejects that blob | 0 or 1 |

## Outputs

| Path | Type | Meaning |
| --- | --- | --- |
| ${azure_put.output.allFilesUploaded} | ENUM | `YES`, or `NO` when at least one file was not uploaded; branch on it with a `SWITCH`. |
| ${azure_put.output.listing} | FILE | XML `<Azure-Storage-Blob-Put-Listing>` with, per attempted file, `<Name>`, `<Response>` (`Content-MD5`, always empty for block blobs; `Date`; `Error-Code`, empty on success; `Last-Modified`; `Metadata`) and `<Url>`. |
| ${azure_put.output.report} | FILE | XML execution log; absent when `skipReportGeneration = true`. |

```json
{
  "name": "azure-storage-blob-put",
  "taskReferenceName": "azure_put",
  "description": "Upload the generated product images to the Azure container",
  "type": "SUB_WORKFLOW",
  "optional": false,
  "inputParameters": {
    "authenticationMode": "CONNECTION_STRING",
    "connectionString": "${workflow.globalVariables.azure_connection_string}",
    "container": "your-container",
    "request": "${build_request.output.result}"
  }
}
```

## Gotchas and limits

- Limits: maximum 1000 files, maximum file size 2 GB, global maximum 20 GB. They are not checked up-front: reaching one interrupts the upload part-way (files already sent stay, the rest is never attempted, the error goes to `report` and `allFilesUploaded` is `NO`).
- A `File` without `Name` or `Url`, or with an unresolvable extension, is skipped without failing the task; the reason is logged in `report` and `listing` only holds the attempted files. Always check `allFilesUploaded` downstream.
- Metadata element names are sent as-is; an invalid name makes Azure reject that blob.
- Credentials belong in secret global variables; the documentation examples use literal placeholders.
- Report inputs: `skipReportGeneration` (default `false`) and `logLevel` (default `info`).
- Required per schema: `authenticationMode`, `container` and `request` (same as the documentation). Leave out any key that the input table does not list.
