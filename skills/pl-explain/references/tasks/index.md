# Data Factory task catalog

> Reference token: DF-TASKS-INDEX-01

This index lists every catalog task documented at `https://learn.product-live.com/data-factory/references/tasks/<task-name>/`, one row per task, with a link to its reference file in this folder.

How a catalog task is declared in `job.json`: the task object's `name` is the catalog task name (for example `data-item-find`), its `type` is always `SUB_WORKFLOW`, and its parameters go under `inputParameters`. Every task also carries a unique snake_case `taskReferenceName` (used downstream as `${<taskReferenceName>.output.<path>}`), a functional `description` and the `optional` flag (`true`: the job continues when the task fails; `false`: the job fails). Flow-control tasks (`SWITCH`, `DO_WHILE`, `TERMINATE`, `SET_VARIABLE`, `WAIT`, and the deprecated `DECISION`) put the keyword in `type` instead; they have their own rows and files below (category `logic`, also written `flow-control`) and their wiring is explained in `control-flow.md`.

How to read a task file: each file starts with a reference token, then one line giving the status, the category and the public documentation URL; "Purpose", "When to use" and "When not to use" frame the choice; "Inputs" lists every documented `inputParameters` key (nested keys as dotted names, for example `request.method`) with its type, whether it is required, its default and its allowed values, followed by the request grammar when the task takes a request document; "Outputs" gives the exact downstream paths; "Example" is one minimal valid task object; "Gotchas and limits" collects numeric limits, documented traps and documentation defects; "Related tasks" points to the usual companions.

Status meanings:

- `GA`: generally available.
- `alpha`: a recent task (the documentation shows it in alpha phase), available on every account; use it like a GA task.
- `deprecated`: still accepted but replaced by the task named in parentheses.

Categories (derived from the task name prefix):

- `table`: import, export, refresh and delete items or schemas of a table.
- `file-transformation`: XSLT transformations, XML split and merge.
- `file-conversion`: XLSX, CSV and JSON to XML, archives.
- `file-generation`: XLSX, PDF and archive generation.
- `file-validation`: XSD validation.
- `protocol`: FTP, HTTP and SOAP exchanges (`protocol-ftp-*`, `protocol-http-perform`, `protocol-soap-perform`, the deprecated `protocol-rest-perform`); rows may carry the sub-prefix (`protocol-ftp`, `protocol-http`, `protocol-soap`, `protocol-rest`).
- `notification`: emails and on-screen messages.
- `rules-engine`: execute, import, export rules and rule reports.
- `storage`: cloud storage (Azure Storage blobs).
- `exchange`: send and receive items, publications and suggestions between partner accounts.
- `ai`: calls to a language model.
- `code`: JavaScript execution in the platform's sandbox (`code-execute-javascript`) and jq transformations (`json-transform-jq`, row category `json-transform`).
- `data`: platform data (accounts, items, fields, jobs, projects, partners, logs, current account and user); all alpha.
- `logic` (also written `flow-control`): switch, loop, terminate, set-variable, wait, decision.
- `orchestration`: batch execution of a task over many inputs (`task-batch-execute`, row category `task`) and account-specific custom tasks (`custom-task`).
